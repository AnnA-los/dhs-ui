设计原则

  • 继续使用 app-container、搜索表单、工具栏、el-table、分页、el-dialog 和 RightToolbar 组合。
  • 按钮使用现有 Element 图标和 v-hasPermi 权限控制；危险操作保留二次确认。
  • 表单字段必须有可见 label；只读字段用 disabled 或纯文本说明，和可编辑字段区分。
  • 远程下拉需要支持历史回显；员工、角色、部门等提交 ID，展示名称。
  • 时间范围清空后恢复默认最近一个月，快捷项固定为最近一个月、三个月、半年、一年。
  • 系统超管和医院超管的导航、消息、医院上下文展示分离。

部门、角色、菜单

页面布局权限差异
医院部门树形表格；操作列增加“新增子部门”；上级部门用树选择。第 11 层前端阻止保存，后端兜底。
医院角色列表去掉默认列；角色名称、角色层级、状态、创建时间、操作等按现有后台表格展示。编辑弹窗中角色名称和角色层级置灰不可修改，权限树只展示自己已有权限。默认角色修改权限时，对用户无感复制为当前医院替换角色并迁移成员；默认角色停用或删除前必须无成员，有成员时提示不可操作。owner 可见全部医疗权限；非 owner 不能授予自己没有的权限。
系统菜单业务菜单显示默认可见角色多选：超级管理员、合伙人、管理员、员工；旁边显示说明文字，不展示角色层级数字。新增业务菜单必选；编辑默认可见角色会影响仍使用默认角色的医院，不影响已替换默认角色的医院。

系统消息与邀请审核

页面结构异常/空状态
系统消息发送搜索区按标题、目标类型、发送状态；列表展示标题、目标、发送数量、状态、创建时间；弹窗填写标题、内容、目标类型和值。目标解析为空时不允许发送；发送失败展示失败原因。
右上角消息复用现有通知 popover；系统消息和医院消息按时间倒序展示，未读带圆点。无消息展示“暂无消息”；点击消息后标记已读。
邀请审核页签：待审核、审核通过、审核拒绝；列表展示申请人、手机号、邀请人、邀请码、状态和时间。通过弹窗必须选角色、部门、岗位；拒绝弹窗必须填拒绝原因；拒绝后可再次申请。

短信配置与登录注册

页面字段/交互特殊状态
短信渠道渠道编码、渠道名称、启用状态、创建时间；新增可填编码名称，编辑编码和名称置灰。存在启用模板或场景关联时禁用/删除需后端拦截并提示。
短信模板模板编码、模板名称、场景编码、渠道名称、签名、优先级、状态；编辑编码和名称置灰。渠道下拉展示渠道名称，提交渠道编码。
场景关联场景编码、短信模板下拉、状态；同一场景只能一条启用。模板下拉展示模板名称，提交模板编码。
发送日志手机号、模板名称、场景编码、状态、渠道名称筛选；列表手机号和错误详情脱敏。失败原因可用弹窗查看脱敏详情。
登录注册只保留手机号入口；邮箱 Tab 和邮箱输入移除。真实短信关闭时验证码输入和发送按钮隐藏；系统图形验证码是否保留按后端配置。

状态与验收

状态页面处理
加载中沿用 v-loading，按钮保存期间显示 loading 或禁用。
空数据Element 表格默认空态；关键审核/消息页面空态文案保持简短。
无权限按钮隐藏或禁用；后端拒绝时展示后端错误信息。
重复提交保持全局 request 1 秒重复提交拦截，页面不吞掉错误。
移动窄屏后台主要面向桌面；弹窗宽度使用 560-760px，窄屏按 Element 默认自适应滚动。
